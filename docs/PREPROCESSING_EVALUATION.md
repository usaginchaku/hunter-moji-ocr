# 極性・低コントラスト前処理の比較

## 原因と変更範囲

変更前の基準は `c1a31c8`。画像のデコード、白いCanvasへの描画、切り抜き、最大辺2048pxへの縮小の後、`src/image/load.ts` の6方式で二値化し、Workerで分割・照合・方式選択を行う。

6方式すべてが暗い画素を文字と仮定していた。背景色との差方式は背景より暗いことを要求し、黒い線優先方式は暗い背景を前景へ変換する。局所コントラスト、局所色差、Sauvola、無彩色の黒線も暗色を抽出する。明色の文字に適した候補がないため、自動選択の変更だけでは直らない。低コントラスト画像では、固定の色差・輝度差の下限で線が消える。

今回追加する処理は、6方式に渡すRGBAの極性・コントラスト補正に限定する。既存の二値化、分割、照合、方式の優先度、UI構成は変更しない。

1. 処理対象範囲の輝度ヒストグラムと外周の輝度分布を調べる。
2. Otsuのクラス間分散から明暗の分離を評価する。分離度0.8以上、クラス平均の輝度差12以上、両クラスがそれぞれ0.3%以上ある場合だけ極性を確定する。
3. 全体の55%以上と外周の85%以上が暗側なら明色文字とし、RGBを反転する。明側で同じ条件が成立すれば暗色文字とする。平均輝度が暗いという理由だけでは反転しない。
4. さらに分離度0.9以上、平均輝度差64以下、95%以上の画素がほぼ無彩色の場合だけ、クラス平均の間を0〜255に伸長する。
5. 判定不能または補正不要な画像は、元のRGBAをそのまま既存処理へ渡す。

Otsuは極性と補正可否を調べるために使い、既存の6方式を一律に置き換えない。[OpenCV公式の二値化解説](https://docs.opencv.org/4.13.0/d7/d4d/tutorial_py_thresholding.html)を参照。透明画素は既存の白Canvasと同様に扱う。入力配列は変更しない。

プレビュー、1文字照合、複数文字認識は同じ読み込み経路を使う。補正内容は既存の方式名に表示し、判定しきい値・分離度・背景占有率・輝度範囲はブラウザのデバッグログ `OCR前処理` と各variantの `preprocessing` に残す。

## 比較方法

`tests/fixtures/preprocessing-evaluation.html` は、独自SVG全47字を含む14文字列を8配色でCanvas描画する。濁点、半濁点、小書き、3行構成も含む。PNGのデコードから実際の6方式・自動選択・最終かな合成まで通す。合成112画像の成績であり、実グッズ画像の精度とは区別する。

変更前は補正を通さず、変更後は実際の画像読み込み関数を通す。比較用の6関数は変更していない。同じ文字列・テンプレートで全6方式の二値画素が完全一致するときだけ、決定的な認識計算を再利用する。ハッシュの一致で代用しない。タイミング値は再利用を含むため、変更前後の速度比較には使わない。

再実行:

```sh
npm run dev -- --host 127.0.0.1
```

表示された開発サーバーの `/tests/fixtures/preprocessing-evaluation.html` を開く。最終結果はページ内にJSONで表示される。実行中にソースを編集するとViteの再読み込みで評価が最初からになるため、コードを固定して実行する。

各画像の文字精度は `max(0, 正解文字数 - 編集距離) / 正解文字数`。全文一致は改行も含めて比較する。「要確認」は既存のスコア・候補差・修飾・小書きの判定を使い、認識された候補数を分母にする。未抽出文字は文字精度・全文一致で失敗に残す。

69/73は94.52%、13/14は92.86%。全112画像で文字精度の悪化なし。白背景・黒文字、グレー背景・黒文字、淡色背景・オレンジ文字の計42画像は、全6方式の二値画素が完全一致した。失敗は各配色の3行画像1枚で、最下行だけを選ぶ既存の選択ロジックによる4文字の未抽出。

各画像の出力と設定は [比較結果JSON](preprocessing-evaluation-results.json) に保存。濁点の合成ケースは5種類を配色変更した40文字が正解したが、生成例かつ少数の字種なので濁点95%の一般的な達成判定には使わない。

別途、非生成のグッズ紹介画像88枚・322文字も再測定し、全画像・全6方式の二値画素と自動認識結果が変更前と同一だった。現行の文字精度は82/322、全文一致3/88であり、前処理による退行はないが、複雑背景の実用精度には達していない。詳細は [実画像評価](REAL_IMAGE_EVALUATION.md) を参照。

単体テストは変更前167件に対し、前処理・読み込み統合・最終文字列カテゴリ評価を含めて200件。Lint、TypeScript、ビルド、変更ファイルの整形を確認した。全体の整形チェックでは既存の未追跡 `docs/failure-reports/README.md` の警告が残り、その資料は変更していない。

## 既存JPEGの局所再現

ローカルの既存不具合報告画像（紺背景・黄色文字、576×368、3行13文字）も確認した。元の画像・報告書は今回変更しない。

- 補正前: 背景方式の前景率0%、黒い線優先方式の前景率90.27%。自動選択は2候補で文字精度0/13。
- 補正後: 明色文字判定、検出用しきい値114、分離度0.953、外周暗色率100%。背景方式の前景率9.08%、3行13候補を抽出。
- 背景方式を指定した最終出力は13/13・全文一致、要確認1/13。
- 自動選択では既存の最下行優先処理が選ばれ、4/13・全文不一致。これは前処理とは別の残存問題。

## 制約と次の検証

外周と内部が食い違う額縁付き画像、明暗が混在する文字、背景が多数派でない狭すぎる切り抜き、非常に弱い輝度差、複雑な模様では極性を確定しないことがある。既存の範囲切り抜きで文字と背景を含む単純な領域を選んで確認する。

前処理を通しても、既存の字形照合・濁点判定・複数行の自動選択に由来する誤りは残る。次に最下行だけを選ぶ問題と、ローカル実グッズ画像の失敗を、通常画像の回帰比較を保ちながら切り分ける。
